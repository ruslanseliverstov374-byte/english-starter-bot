# Запуск бота 24/7

Бот умеет работать в двух режимах и сам выбирает нужный:

| Режим | Когда включается | Что нужно |
|---|---|---|
| **long polling** | переменная `WEBHOOK_URL` не задана | только исходящий интернет, порты не нужны |
| **webhook** | задана `WEBHOOK_URL` (публичный HTTPS-адрес) | открытый порт `PORT`, HTTPS-адрес |

Напоминания (по умолчанию 09:00 по выбранному часовому поясу) работают в обоих режимах —
но только пока процесс бота запущен.

## Сколько стоит 24/7 (актуально на 2026 год)

Боту нужно меньше 100 МБ памяти и почти ноль процессора, поэтому хватает самого дешёвого сервера.

| Вариант | Цена | Что получаете | Нюансы |
|---|---|---|---|
| **Свой ПК** (`install_autostart.bat`) | **0 ₽** | автозапуск при входе + сторож каждые 5 минут | работает, только пока компьютер включён и не спит |
| **VPS в РФ, 1 ядро / 1 ГБ** (Aeza, Timeweb Cloud, FirstVDS, VDSina) | **150–300 ₽/мес** (~2 000–3 500 ₽/год) | круглосуточно, свой диск, полный контроль | 15 минут настройки — делается одной командой ниже |
| **Hetzner CX22 / DigitalOcean** | 350–450 ₽/мес | то же, стабильнее и быстрее | нужна зарубежная карта |
| **Render Starter + диск** | ~650 ₽/мес + ~20 ₽ за диск | ничего администрировать не надо | дороже VPS, но проще всего |
| **Oracle Cloud Always Free** | **0 ₽ навсегда** (2 ARM-ядра, 12 ГБ) | полноценный сервер бесплатно | нужна карта для регистрации, бывают отказы и отбор простаивающих серверов |

**Рекомендация для этого бота: VPS за 200–300 ₽/мес** (Ubuntu 22.04/24.04, 1 vCPU, 1 ГБ RAM, 10 ГБ SSD).
Домен и SSL не нужны: режим long polling не требует ни портов, ни HTTPS.

Что спросить у провайдера при заказе: «VPS, Ubuntu 24.04, 1 vCPU, 1 ГБ RAM, 10 ГБ NVMe, доступ root по паролю».

## Установка на VPS одной командой

На вашем компьютере (Windows) откройте PowerShell в папке проекта и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\deploy_to_vps.ps1 -Server <IP_СЕРВЕРА>
```

Скрипт сам: соберёт архив, сделает согласованный снимок базы (прогресс переедет вместе с ботом),
скопирует всё на сервер, поставит python3, создаст systemd-сервис с автозапуском и перезапуском
при падении, включит ежедневную резервную копию в Telegram и самопроверку каждые 5 минут,
проверит связь с Telegram и покажет статус.

Короткая версия этой инструкции (что купить и что прислать) — [QUICKSTART-VPS.md](QUICKSTART-VPS.md).

Дальше останется один шаг — **выключить автозапуск на ПК**, чтобы два бота не мешали друг другу:

```
remove_autostart.bat   (двойной клик)
```

Обновить код на сервере после правок (прогресс не трогается):

```powershell
powershell -ExecutionPolicy Bypass -File deploy\update_vps.ps1 -Server <IP_СЕРВЕРА>
```

На сервере доступны команды:

```bash
systemctl status english-starter      # состояние
journalctl -u english-starter -f      # живые логи
systemctl restart english-starter     # перезапуск
systemctl list-timers | grep english  # когда следующая резервная копия и самопроверка
```

Если провайдер дал не root, а пользователя `ubuntu` (и/или нестандартный порт):

```powershell
powershell -ExecutionPolicy Bypass -File deploy\deploy_to_vps.ps1 -Server <IP> -User ubuntu -Port 2222
```

# Варианты попроще (для справки)

## Вариант A. Свой компьютер (0 ₽)

1. **Автозапуск со сторожем** — двойной клик по `install_autostart.bat`. Скрипт создаст две задачи
   в планировщике Windows: запуск бота при входе в систему и проверку каждые 5 минут
   («если бот упал — поднять»). Окно консоли не появляется, логи — в `logs\bot.log`.
2. Без автозапуска: `setup.bat` (или `run.bat`) — бот работает, пока окно открыто,
   и сам перезапускается после падения.
3. Отключить автозапуск и остановить бота: `remove_autostart.bat`.

**Обязательно сделайте это перед переездом на сервер** — иначе два бота будут мешать друг другу
(Telegram отдаёт обновления только одному; бот напишет об этом в `logs\bot.log`).

Минус варианта: пока компьютер выключен или спит — бот молчит, напоминания не приходят.
Прогресс не теряется: он в `data/bot.db` и ждёт вас.

## Вариант B. VPS (24/7) — другие способы установки

Основной способ — одна команда из начала этого файла (`deploy_to_vps.ps1`).
Ниже — альтернативы, если хотите ставить руками.

### B1. Docker

```bash
# 1. установить Docker одной командой
curl -fsSL https://get.docker.com | sh

# 2. скопировать проект на сервер (выполняется на вашем компьютере)
scp -r english-bot root@<IP-сервера>:/opt/

# 3. собрать образ
cd /opt/english-bot
docker build -t english-bot -f deploy/Dockerfile .

# 4. запустить бота: данные в томе engbot-data, автозапуск после перезагрузки
docker run -d --name english-bot --restart unless-stopped \
  -e BOT_TOKEN=8123456789:AAH... \
  -v engbot-data:/data \
  english-bot

# 5. смотреть логи
docker logs -f english-bot
```

Обновление после правок:

```bash
cd /opt/english-bot && docker build -t english-bot -f deploy/Dockerfile . && docker restart english-bot
```

Резервная копия прогресса:

```bash
docker run --rm -v engbot-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/bot-backup-$(date +%F).tgz -C /data .
```

Режим long polling на VPS домен и порты не требует — Telegram сам отдаёт обновления боту.

### B2. Без Docker (systemd)

Ставится тем же установщиком — он написан на Python, поэтому работает на голом Ubuntu
без bash-хитростей и сам создаёт все четыре юнита:

```bash
# на сервере, от root (файлы проекта уже скопированы в /opt/english-bot)
python3 /opt/english-bot/deploy/vps_install.py '8123456789:AAH...' --app-dir /opt/english-bot
```

Проверить, что установщик сделает, ничего не меняя (работает и на Windows):

```bash
python3 deploy/vps_install.py ТОКЕН --dry-run --app-dir ./tests/_run/vps
```

Установщик создаёт:

| Юнит | Зачем |
|---|---|
| `english-starter.service` | сам бот: автозапуск при загрузке + перезапуск при падении через 5 с |
| `english-starter-backup.timer` | ежедневная резервная копия прогресса в Telegram (20:00) |
| `english-starter-healthcheck.timer` | каждые 5 минут проверяет «отметку жизни» и перезапускает зависшего бота |

## Вариант C. Render, бесплатный тариф (webhook)

Плюс: бесплатно и без своей машины. Минусы: бесплатный сервис засыпает без запросов,
а постоянный диск — платная опция.

1. Залейте папку `english-bot` в репозиторий GitHub.
2. В Render: **New** → **Blueprint** → выберите репозиторий (Render прочитает `render.yaml`).
3. В переменных окружения задайте:
   * `BOT_TOKEN` — токен от @BotFather;
   * `WEBHOOK_URL` — адрес сервиса, который выдаст Render, например `https://english-starter-bot.onrender.com`
     (без слэша в конце);
   * `WEBHOOK_SECRET` Render сгенерирует сам.
4. Дождитесь сборки. Render проверит `healthCheckPath: /` — бот должен ответить `English Starter bot is alive`.
5. **Обязательно:** чтобы сервис не засыпал и напоминания приходили, поставьте внешний пинг
   каждые 5–10 минут (бесплатно: cron-job.org, UptimeRobot, healthchecks.io) — GET на адрес сервиса.
   Без пинга бот проснётся только когда вы сами напишете ему в Telegram, и утреннее
   напоминание может не прийти.

Проверка webhook:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

Должны увидеть свой `url`, `pending_update_count: 0` и отсутствие `last_error_message`.

### Хранение прогресса на Render

* Бесплатный тариф: файловая система временная — при перезапуске `data/bot.db` теряется.
  Для личного использования это терпимо, но прогресс лучше не терять.
* Надёжнее: платный диск Render (Disks, ~1–2 $/мес) с точкой монтирования `/data`
  и переменной `DB_PATH=/data/bot.db`, либо вариант B (VPS), где том `engbot-data` постоянный.

## Прогресс не должен теряться: резервные копии в Telegram

Даже если сервер потеряет диск (или на бесплатном тарифе файловая система временная),
прогресс можно вернуть: копия базы лежит у вас в переписке с ботом.

* `/backup` — бот присылает файл `english-starter-backup.db` в чат владельца
  (владелец = `ADMIN_CHAT_ID`, иначе самый первый ученик).
* Автоматически: раз в 2 дня при запуске бота, а на VPS ещё и каждый день в 20:00
  (systemd-таймер `english-starter-backup`).
* **Восстановление**: отправьте (или перешлите) этот файл боту — он заменит базу, сохранит
  прежнюю рядом как `bot.db.before-restore` и подтвердит результат. Может только владелец.
* Отключить автокопии: `AUTO_BACKUP=0` в `.env`.

Совет: пересылайте файлы себе в «Избранное» — тогда копия не зависит ни от сервера, ни от бота.

## Что проверить после запуска в облаке

1. В логах: `Бот запущен: @имя_бота` и, для webhook-режима, `Webhook установлен: https://...`.
2. В Telegram: `/start` → онбординг проходит, урок дня доходит до конца.
3. `/progress` показывает ваш прогресс.
4. `/backup` — приходит файл с базой (значит, восстановление тоже сработает).
5. Через минуту после запуска напоминаний — тест: `/settings` → «Время напоминания» →
   поставьте время на 2 минуты вперёд → напоминание должно прийти.
6. Перезапустите сервис и убедитесь, что `/progress` сохранил данные (проверка тома).

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Unauthorized` в логах | неверный токен — проверьте `BOT_TOKEN` |
| Бот молчит после запуска | занят другим процессом: два экземпляра не могут одновременно читать `getUpdates`; остановите лишний |
| `Conflict: terminated by other getUpdates request` | запущена вторая копия бота (ПК + сервер) или остался webhook. Остановите лишний экземпляр (`remove_autostart.bat` на ПК). Бот сам останавливается после 5 таких ошибок и создаёт `data/conflict.flag` |
| `Бот уже запущен (блокировка ... занята)` | защита от дублей сработала: второй процесс на той же базе. Остановите лишний процесс |
| Напоминания не приходят | сервис спит (вариант C), либо нажат `/stop`, либо другое время/пояс — проверьте `/settings` |
| Прогресс пропал после перезапуска | том/диск не подключён: `DB_PATH` должен указывать на постоянный каталог (`/data/bot.db`). Спасает `/backup` — пришлите файл боту |
