# Бесплатный 24/7: схема, которая реально работает

Бот живёт в облаке бесплатно, без вашего компьютера и без ежемесячных платежей.

```
GitHub (код)  →  Render Free (сам бот, webhook)  →  Telegram
      ↑                    ↑                            ↑
 keepalive.yml       пинг /health              закреплённая копия базы
 (раз в 5 минут)   (Render сам или ПК)          (хранится в чате владельца)
```

Ключевая идея: **резервная копия базы живёт в самом Telegram.** Бот отправляет сжатый
снимок базы в чат владельца и закрепляет его, а после перезапуска контейнера читает
закреплённое сообщение через `getChat` и восстанавливает прогресс **автоматически**.
Никаких сторонних сервисов, регистраций и банковских карт не требуется.

| Часть | Зачем | Цена |
|---|---|---|
| **Render Free** | запускает бота, даёт публичный HTTPS-адрес для Telegram | 0 ₽, карта не нужна |
| **Копия в Telegram** | диск у бесплатного Render временный: перезапустили контейнер — база пропала; закреплённый файл в чате переживает всё | 0 ₽ |
| **Пинг** (GitHub Actions или ПК) | спящий сервис не может отправить напоминание | 0 ₽ |
| **GitHub** | откуда Render берёт код | 0 ₽ |

Без пинга бот тоже работает: он просыпается от вашего сообщения (30–60 секунд на первый
ответ) и «догоняет» пропущенные напоминания при следующем обращении.

---

## Шаг 1. Выложить код на GitHub

1. Зарегистрируйтесь на [github.com](https://github.com) (бесплатно, карта не нужна).
2. **New repository** → имя `english-starter-bot` → **Private** или Public → **Create repository**.
3. **Add file → Upload files** → перетащите файлы из архива `english-bot-github.zip`
   (собирается командой `python tools/make_github_zip.py`) → **Commit changes**.

## Шаг 2. Запустить на Render

1. [render.com](https://render.com) → **Get Started** → вход **через GitHub**.
2. **New → Blueprint** → выбрать репозиторий `english-starter-bot`.
3. **Blueprint Name:** `english-starter-bot` · **Branch:** `main` · **Blueprint Path:** пусто.
4. Render прочитает `render.yaml` и попросит заполнить переменные:
   * **`BOT_TOKEN`** — токен от @BotFather (обязательно);
   * `ADMIN_CHAT_ID` — ваш числовой chat id (необязательно: бот определит владельца сам
     при первом сообщении и найдёт закреплённую копию именно в его чате);
   * `SNAPSHOT_URL` / `SNAPSHOT_TOKEN` — **оставьте пустыми**: они нужны только для
     внешнего key-value хранилища, а у нас копии в Telegram.
5. **Deploy Blueprint** → дождаться статуса **Live** и скопировать адрес сервиса
   вида `https://english-starter-bot.onrender.com`.

## Шаг 3. Написать боту `/start`

Первый, кто напишет боту после холодного старта, получает прогресс автоматически:
если база пустая, а в его чате есть закреплённая копия — бот поднимет её целиком и
ответит «♻️ Прогресс восстановлен».

Дальше копии обновляются сами: раз в 30 минут, после каждого урока и при остановке.
Отправляются тихо (без звука), предыдущая копия удаляется — чат не мусорится.

## Шаг 4. Пинг, чтобы сервис не засыпал

**Вариант А — GitHub Actions (круглосуточно, настраивать нечего).**
Файл `.github/workflows/keepalive.yml` уже в репозитории: раз в 5 минут дёргает `/health`.
Адрес сервиса прописан внутри; при переименовании сервиса задайте переменную репозитория
`BOT_URL` (Settings → Secrets and variables → Actions → Variables).
Нюанс: GitHub отключает расписание после 60 дней без активности в репозитории — поэтому полезен вариант Б.

**Вариант Б — пинг с вашего компьютера (без аккаунтов).**
Двойной клик по `install_ping.bat`: создаст задачу «каждые 5 минут дёргать /health»,
лог — `logs\ping.log`. Работает, пока компьютер включён.
Снять: `python tools\install_ping.py --remove`.

**Вариант В — [cron-job.org](https://cron-job.org)** (регистрация по email, бесплатно):
Create cronjob → URL `https://ваш-сервис.onrender.com/health` → каждые 5 минут.

## Шаг 5. Выключить локальную копию

Чтобы два бота не спорили за обновления Telegram:
* включали автозапуск — `remove_autostart.bat`;
* иначе — `python tools/stop_bot.py` или просто закройте окно бота.

## Как проверить, что всё работает

| Что | Как проверить |
|---|---|
| Бот жив | `https://ваш-сервис.onrender.com/health` → `ok` |
| Статистика проекта | страница `https://ваш-сервис.onrender.com/` (годится для портфолио) |
| Копии работают | в чате закреплено сообщение с файлом; на странице видно «последний сигнал пинга» |
| Восстановление | Render → Manual Deploy, затем написать боту: придёт «♻️ Прогресс восстановлен» |
| Пинг | `logs\ping.log` (ПК) или GitHub → Actions → keepalive |
| Напоминания | `/settings` → время на 2 минуты вперёд → напоминание придёт |

## Ограничения, о которых честно стоит знать

1. **Холодный старт.** Без пинга сервис засыпает через 15 минут, первый ответ — 30–60 секунд.
2. **750 часов в месяц** на бесплатном Render: круглосуточно ≈ 730 ч — влезает, но запаса почти нет.
3. **Диск контейнера временный** — поэтому и нужны копии в Telegram; ничего важного вне базы бот не пишет.
4. **Расписание GitHub** может задерживаться на несколько минут и отключается после
   60 дней простоя репозитория — держите вариант Б.
5. **Данные в чате:** закреплённая копия содержит имена и chat_id учеников — видна только
   вам и боту, наружу ничего не уходит.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| `Conflict: terminated by other getUpdates request` | где-то ещё работает копия бота — остановите лишнюю |
| Бот молчит, в логах Render пусто | не задан `BOT_TOKEN` или сервис ещё собирается |
| `ModuleNotFoundError` в логах | в `deploy/Dockerfile` должно быть `COPY *.py ./` (копирует все модули) |
| Прогресс обнулился и не восстановился | не написан `/start` после перезапуска, либо копия удалена — пришлите боту файл копии из чата |
| Напоминания не приходят | нет пинга — сервис спит (шаг 4) |

Проверить всё снаружи можно самому: `python tests/check_cloud.py` (health + статистика)
и `python tests/monitor_cloud.py` (одна строка состояния).
